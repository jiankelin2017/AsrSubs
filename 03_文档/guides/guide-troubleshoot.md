# 指南 · 故障处置

## 一句话摘要

先确认 Resolve 首选项「外部脚本使用 = 本地或网络」，再按现象表对号入座；日志和诊断信息的固定位置是 `data\logs\AsrSubs_error.log` 与顶部版本号。

## 当前有效结论

| 结论 | 依据 |
|---|---|
| 绝大多数「点不动 / 读不到时间线」的第一前提：Resolve 首选项 → 系统 → 常规 → **外部脚本使用**设为「本地」或「网络」 | `03_文档\使用说明.txt`「出问题先看这里」 |
| 「开始生成」是灰的**不是坏了**：无时间线 / 时间线无片段 / 环境自检未过 / 上轮任务仍在跑，四种条件补齐后 3 秒内自动变亮 | `..\CHANGELOG.md` 1.2.0；`03_文档\使用说明.txt`「三步上手」 |
| 日志 / 诊断入口：安装目录 `data\logs\AsrSubs_error.log`（默认 `D:\AsrSubs\data\logs\`），或点界面顶部版本号看诊断信息 | `03_文档\使用说明.txt`「出问题先看这里」 |
| 第一次点「开始生成」可能闪一下命令行窗口（启动后台执行器），之后不会再有 —— **不是报错** | 同上 |

## 关键变更（仅影响使用的里程碑）

- v1.2.0：「开始生成」改为按前置条件置灰，原先「条件不满足也能点、点完干等渲染 20 秒或超时」的现象已消失。
- v4.8.18：模型下载「下不动」已修（会话级不可达源黑名单 + 小文件 20 秒短超时），排查顺序见下。

## 操作 / 参考细节

### 插件内现象速查

| 现象 | 处理 |
|---|---|
| 菜单里没有 AsrSubs | 完全退出 Resolve 后重开 |
| 读取时间线失败 | 检查「外部脚本使用」设置 |
| 适配字幕点不动 | 右侧表格空 = 还没识别成功，点【开始生成】重来；表格有字幕但按钮灰，关掉插件重开一次（按钮状态随表格刷新） |
| 识别很慢 | 状态栏写「CPU 模式」即没用到显卡：重跑安装器选 GPU 版 |
| 表格没有黄底 | 先在「查找」框输入关键词；命中行才有底色 |
| 视频粗剪是灰的 | 三种原因，状态栏会写：没删过行 / SRT 还没写回 / 正有任务在跑 |
| 撤销没反应 | 撤销只有一级；上一步什么都没改则不生成快照 |
| 字幕比 SRT 少几条 | Resolve 会合并「不足一帧」「同帧起始」「时间重叠」的条目，日志会指认；调大「每行字数」可减少条目数 |
| 热词那行空着 | 缺 jieba：在安装目录执行 `runtime\Scripts\python.exe -m pip install jieba`，然后点「读取媒体池字幕」或重开插件，不用重识别 |
| 进度条不动 / 报错 | 点顶部版本号看诊断信息，或看 `data\logs\AsrSubs_error.log` |

### 安装类故障排查顺序

```
1. 看 models\ 里两个权重（约 1.8 GB × 2）与 8 个文件是否都已就位
2. 看 _setup\_deployed.json 是否已部署
3. 再决定：继续等 / 杀进程 / 修代码
```

历史案例：用户报「下不动」时，权重其实早已下完，进程只是在对镜像站未收录的可选小文件做无谓重试（每个不可达源干等 60 秒 × 2 遍，白等 20~40 分钟）。当前版本已修，但**排查顺序仍然有效**。

### 「部署一致」失败怎么处置（历史，2026-11-05 已修复）

2026-11-05 早间该项确实失败：源码 1.2.0、payload、安装包都齐，但 `%ProgramData%` 里的菜单 Lua 是 378,114 B（11-03）旧版。第 5 批已用「备份 → 手动 copy 两处 → 复跑验收」修复，22:53 复跑 18 项全绿。**排查顺序仍有效**：① 确认两处部署副本（`%ProgramData%` + `D:\AsrSubs\engine`）的 `AsrSubs.lua` 与源码 MD5 一致；② 确认 `--<<INSTALL_ROOT>>` 锚点仍在；③ 确认 `D:\AsrSubs\engine\paths.json` 字段齐全且 `engine` 指向自己；④ 重跑验收。注意 `check_deploy()` 不比 engine 的 `.py`，该项转绿**不代表引擎已升级**。

## 失效内容说明

- 「条件不满足也能点【开始生成】」是 1.2.0 之前的现象，已由 `App:CanStart()` 前置判据取代。
- 「选了 GPU 却跑 CPU」分两种：旧安装器（v4.8.23，成品已移出）的缺陷已修；当前若状态栏显示「CPU 模式」，按上表重跑安装器选 GPU 版。
- `03_文档\archive\archive-uninstall-fix-20261030.md`（v1.28）记录的「卸载把字幕一起删」「`{tmp}` 不是 `%TEMP%`」是历史缺陷，当前安装器已改；保留为历史根因，见 `..\reference\reference-installer-pitfalls.md`，**不要照它现在的代码路径去改配置**。
