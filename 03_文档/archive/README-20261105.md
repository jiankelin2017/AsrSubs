# AsrSubs — DaVinci Resolve 离线字幕插件

在 DaVinci Resolve 里把时间线的音频识别成字幕，全程本地推理，音频不出机器。
识别模型：Qwen3-ASR-0.6B + Qwen3-ForcedAligner-0.6B（词级强制对齐）。

**运行版本：v1.2.0** · 功能描述以 **4.0.9** 为基线编写，4.2 → 4.8.14 的界面重构与新增项见
`03_文档\开发文档.md` §6.10；v4.8.24 的 11 项体验优化见 §6.11，v4.8.25 的 5 项容错修复见 §6.12，v4.8.26 的单实例保护见 §6.13，v1.0.0 的版本重置与两处修复见 §6.14，v1.0.1 的 18 处体验修复见 §6.15，v1.1.0 的一键安装/卸载见 §6.16，v1.1.1 的关窗切页修复见 §6.17，v1.2.0 的句末标点收口 / 按钮前置条件 / 裁剪区间复位见 §6.18。

> 更完整的开发者技术参考见 `03_文档\开发文档.md`（架构、模块、R1/R2/R3 重构、v4.2–v4.8.14 界面重构、测试体系、同步工作流）。

> **v1.2.0（2026-11-05，句末标点收口 + 「开始生成」前置条件 + 裁剪区间复位；识别算法零改动）**
>
> - **「句末无标点」勾了仍有行尾逗号 —— 已修**（用户报的第 1 个问题）。
>   根因是**后处理顺序**：`strip_tail_punct` 只在切句后执行一次，后面还有三条会
>   重新切分文本的路径（长条再切 `resplit_overlong_blocks`、长停顿断行
>   `split_at_long_pauses`、写盘前超宽再折 `refold_overlong_text`），三条都
>   **优先切在标点之后**，于是又造出「…欢聚一堂，」这种行尾。最后一条正好在写盘前，
>   必然进 SRT。复现（8 字档）：三条路径分别产出 `…欢聚一堂，` / `聚一堂，` / `…欢聚一堂，`。
>   修法：`run()` 在 `refold_overlong_text` 之后加一道**出口收口**，仅当
>   `no_punct` / `strip_all_punct` 开启时对每条做行尾标点清扫，清空则丢弃该块。
> - **「开始生成」按前置条件置灰**（用户报的第 2 个问题）。新增 `App:CanStart()`：
>   ① 相位在 `BUSY_PHASES` 内 → 灰；② 环境自检有缺失（引擎脚本 / Python）→ 灰；
>   ③ 取不到时间线，或音轨+视频轨上一个片段都没有 → 灰。判据全部用同步 API，
>   数到第一个片段就返回（大工程也是常数级）。刷新点：开窗、`EnableButtons`、
>   `Tick` 非忙相位每 3 秒、以及点击时再确认一次。
> - **修复 `audio_trim` 跨轮残留（字幕整体错位）**：`App.S.trimFrom/trimDur` 只在
>   `OnProbe` 里赋值，而 `Tick` 的 probing 超时分支有两条**绕过 `OnProbe`** 的出口
>   （拿到 `src_path.txt` 直接识别 / 直接转渲染）。上一轮"掐头识别"的裁剪区间会被
>   写进本轮 `args.json`，引擎只抽一小段音频，SRT 从 0 起算而画面没动。
>   现在 `App:Start` 里每轮归零。
> - **其余四处（审查发现）**：`KillTasks` 的 worker 不可用兜底分支以前忽略 `all` 参数
>   （`pids.lua` 里没有常驻 `asr_server`，worker 已死时关窗收不掉它，继续占 2~3GB 显存），
>   现在 `all=true` 时按 `asr_hb.txt` 补杀；worker 单实例锁在"锁文件刚建、内容还没落盘"
>   时会被误判成残留并删除（可能让两个 worker 并存），改为 60 秒内一律让路；
>   `acquire_single` 的裸 fd 在 `fdopen` 失败时泄漏，补 `os.close`；
>   `lateImportUntil` 未在新一轮 `Start` 清零，会把本轮正常导入再报一遍"（迟到）"。

> **v1.1.1（2026-11-01，修「关窗跳到交付页」；插件功能零改动）**
>
> 现象：打开 AsrSubs 什么都不做、直接关窗，DaVinci 自己切到交付页。
> 根因两层叠加：① v1.0.1 让关窗也走 `CleanupRender`，而它无条件
> `DeleteRenderPreset("render_to_wav")` —— Resolve 删渲染预设会切到交付页；
> ② `ReturnToPrevPage` 只看 `StartRender` 留下的 `prevPage`，没渲染过是 nil，
> 于是没人切回来。
> 修法：无快照/无作业时 `CleanupRender` 直接返回（一个交付页 API 都不碰）；
> 切页改用一次性 `pageMoved`，只在真切过页时切回，且已在目标页不重复切。
> 新增 `tools\test_close_page.py`（5 条断言）并进验收（现 17 项）。

> **v1.0.0（2026-11-01，版本号重置 + 两处修复；识别算法零改动）**
>
> **版本号重置**：本项目从 4.8.26 直接改名为 **1.0.0**，此后按三段式走：
> 小更新（修补/文案）动最右一位 `1.0.0 → 1.0.1`；重要更新（成组功能、较大修复）动中间一位
> `1.0.1 → 1.1.0`；超大型更新（架构调整/不兼容）动最左一位 `1.1.0 → 2.0.0`。
> 历史版本号（4.x）在下方旧记录里保持原样，不再改。
>
> - **剩余时间（ETA）重算**：原来拿「已用时间 / 当前百分比」直接外推，而"已用时间"里含
>   模型加载（实测 7~17 秒）、百分比里不含 —— 分母被算大。116 秒素材在 19% 时给出
>   「约剩 1 分 20 秒」，实际只剩 44 秒（**高估 36 秒**）。现在改成
>   **最近 60 秒速率占七成 + 扣掉加载后的全程均速占三成**，并且只在「≥15% 且加载完
>   20 秒后」才显示。按界面实际显示的字回放实测：误差中位 **7s → 3s**、最大 **73s → 11s**
>   （116 秒素材），长素材持平（中位 13s → 15s、最大 61s）。
> - **粗剪清旧字幕改成「按时间码认领」**：原来靠"字幕条目的来源媒体池项名字 == SRT 文件名"，
>   可实测 `TimelineItem.GetMediaPoolItem()` 在字幕轨上**返回 None** —— 这条判据从来没真正
>   生效过，只是偶尔能拿到。SRT 一改名就一条都清不掉，重挂时 `land_inplace` 看见轨上有东西
>   就新开一条轨，结果是 **39 条 + 38 条两条轨叠着**（真机复现）。现在改成两级：
>   名字对得上直接用；对不上就按【时间码吻合比例】判断整条轨是不是我们的 ——
>   ≥90% 整轨清（连本次删掉的那条幽灵也清掉）、60%~90% 只清吻合的、<60% 直接跳过不误删。
>   真机验证：改名后粗剪由「77 条两条轨」变成「38 条一条轨、无重复」；同名路径四段回归全过。

> **v4.8.26 改动（2026-11-01，worker 单实例保护 + 真机端到端复验；识别与排版逻辑零改动）**：
> - **worker 单实例保护**：新进程启动时先抢 `rt\worker.pid`（`O_CREAT|O_EXCL` 原子创建）。
>   已有活着的 worker 就**立刻退出（退出码 0）**，不碰任何文件；抢到才继续。
>   判断"活着"不只看 PID 存在，还要 `QueryFullProcessImageNameW` 确认映像名是 python ——
>   只判存活会因 **PID 复用**指到无关进程，导致 worker 永远起不来。
>   被强杀留下的残锁会在下次启动时清掉并记一行日志。
> - **为什么必须挡**：`rt\cmd.json` 是**单槽**通道，两个 worker 会抢同一条命令。
>   实测踩到过：残留的旧 worker 先抢到 `kill` 并按老逻辑把常驻服务一起杀了，
>   新 worker 只看到"命令消失"，表现出来是「kill 杀了服务 / killall 报缺字段」，
>   看起来像代码 bug，其实是环境里有两个 worker。
> - **闸门位置**：必须在删 `res.lua` / 上一轮 `rc_*.lua` **之前** —— 重复拉起的进程
>   若执行那些清理，会直接打断正在干活的 worker，表现为"命令刚发出去就没了"。
>

> **v4.8.25 改动（2026-11-01，第三轮复测后补的 5 项；识别算法零改动）**：
> - **编码嗅探**：`subs_io.read_text_any` 先看 BOM（UTF-16 LE/BE、UTF-8 BOM），
>   再用「含不含义时间码箭头 `-->`」自检。以前 UTF-16 的字节流在 GBK 下"恰好合法"，
>   被解成乱码后**静默载入 0 条字幕**——记事本「另存为 → Unicode」正是这个格式。
> - **解析失败要说清楚**：文件有内容却解析出 0 块时写 `subs_err.lua`，
>   界面上明示「字幕文件解析失败，详见日志」，不再是一个无声的空表格。
> - **写回失败中文化**：SRT 被记事本 / PR / 播放器占用时，原来界面是一段
>   `PermissionError: [WinError 5] 拒绝访问` 英文堆栈；现在提示「原文件未改动，请关闭后重试」。
> - **停止不再连预热服务一起杀**：worker 的 `kill` 拆成 `kill`（只停当前任务）与
>   `killall`（连常驻 ASR 服务一起收）。点「停止」后服务仍在，下次识别不用再等 12 秒加载；
>   关窗口 / 退出插件仍走 `killall`。
> - **跨片段碎片合并**：`merge_tiny_blocks` 原来只在片段内部合并，实测每 117 秒出现一次的
>   0.30 秒「好，可以。」永远并不掉；现在 `run()` 出口再合并一次。实测 116 秒素材
>   <0.79 秒条目 1 → **0**。
> - **剩余时间预估**：状态栏在识别时给出「正在识别第 3/14 段…（58%，约剩 1 分 10 秒）」，
>   跑过 15 秒且进度过 15% 才估（前期含模型加载，估不准），取整到 10 秒避免数字乱跳。
>

> **v4.8.24 改动（2026-11-01，体验优化 11 项；识别算法本身零改动）**：
> - **GPU 版成为默认**：安装器启动时跑 `nvidia-smi` 探测，有卡就默认选 GPU 版并在选项上写出型号。

>   不足 0.4 秒的碎片并条。实测 24 字档：纯「。」条目 1→0，最长条 6.20s→3.96s，

## 1. 功能（4.0.9 基线，后续增补见开发文档）

> 本节描述 4.0.9 时已经定型的行为；4.2 → 4.8.14 的界面重构（面板布局、轨道清单刷新、
> 参数区重排等）以 `03_文档\开发文档.md` §6.10 为准，代码以 `01_源码\AsrSubs.lua` 为准。

**识别与落轨**
- 本地离线识别，支持单片段直读与多片段渲染后识别
- 自研原地落轨（只在当前时间线挂字幕轨，**绝不新建**），字幕不丢、对齐可靠
- 落轨同时导入媒体池；产物写入 `data\output\`
- 文稿导出 TXT（按 60 列重排，不挤成一行）

**字幕编辑**
- 单击一行即进入编辑，改字实时同步表格
- 查找：输入即高亮命中行（表格铺琥珀底色）＋ 编辑区关键词黄底黄字
- 「确认」定位第一处、「▶」循环下一处，命中计数按行统计
- 替换单个 / 全部替换 / 删除高亮字词（删词不删行）
- 原生多选（Ctrl/Shift）、全选、反选、删除选中行
- 单级撤销（删除行、删字词）

**粗剪（v4.0.7：区间校准 R1）**
- 删除字幕行时按时间区间记账（不是行号）
- **R1**：切除区间改读时间线真实字幕轨位置（`GetItemListInTrack` + `GetStart/GetEnd`），自动校准 SRT 秒↔帧的整体偏移，根治"偏移场景误切 / 空切"
- 原地重建时间线，音画同步前移，字幕按新时间重挂、SRT 同步改写
- 写还原清单，点「撤销」可按清单重建回切除前

**字幕更新闭环（v4.0.7：R2 relang）**
- 「更新字幕 · 写回 SRT」写入 SRT 后，**自动闭环重挂时间线**：记录各字幕轨启用态 → 只删本插件旧字幕（**按落轨边车 `.landed.json` 的帧区间精确删**，不碰用户手工字幕）→ 重挂新字幕 → 恢复其它轨启用态
- 时间线没开着时退化为只同步媒体池，不报错

**落轨稳定性（v4.0.7 / v4.0.8 / v4.0.9 真机实战修正）**
- **不再凭空新建字幕轨**：优先复用本插件的专用字幕轨（靠边车定位），没有才新建 —— 修掉「适配字幕」凭空多出 ST2 的问题
- **失败不污染边车**：落轨 0 条时保留旧边车，不会把下次「字幕更新」的定位带偏
- **失败不留孤儿空轨**（v4.0.8）：落轨失败时把本次自己新建的空字幕轨**自动回收**，不再留下一条空 ST2；SRT 一条字幕都没有时直接早退、连轨道都不碰
- **日志如实反馈**：界面正确显示「已删除旧插件字幕 N 条并重挂」，不再恒显示"无旧字幕"
- **工程整理**（v4.0.9）：归档 2.x 旧打包区 `engine\packer\`（55MB）与 13 个一次性探针/工具；清除 5 个零调用死函数；`verify_all.py` 补入 R1/R2/字幕轨清单三套测试并改用 lupa 做 Lua 编译校验 —— **验收链从「12 项且必红」变成「15 项全绿」**。详见 `删除前备份\99_归档\11_v4.0.9整理_20261031\_总说明.md`
- **面板内字幕轨清单**（v4.0.9）：面板顶部常驻一行 `字幕轨 N 条：ST1(启用·53条)｜ST2(禁用·0条)`，**开窗即刷新、落轨后自动刷新**，旁边有「刷新」按钮（换集/手工改轨后点一下）。Resolve 官方 API 没有轨道折叠/高度能力（真机穷举 + 截图实证），所以改走 Fusion UI 自绘路线 —— **完全不碰时间线，天然不会遮挡视频轨**

**其它**
- 权重词纠错（确定性替换，不靠模型自觉）、断点续跑、热词统计
- 模型下拉切换 / 自定义路径；诊断信息收在右下角版本号里

唯一写文件入口是**「更新字幕 · 写回 SRT」**：写 SRT + 同步 / 闭环重挂。
删除、替换、撤销都只改内存并标脏，不会静默写盘。

## 6. 已知限制

- 安装包本体约 12 MB，运行环境与模型是装完在线下载的（3.4~6 GB），
  断网机器只能先备好 `engine` + `models` 再手工部署。
- 跨窗上下文已关闭（`CTX_CHARS = 0`）：人名/数字在不同窗口的写法可能不一致。
- 热词统计依赖 jieba（在 `runtime` 里），缺失时整行留空，不影响出字幕。
- **表格只能整格染色**：Tree 单元格不支持富文本，词级高亮只在编辑区生效。
- **选中行会盖住命中底色**：Qt 用系统高亮色重绘选中行，这是刻意的优先级。
- **撤销只有一级**：且切除视频后的撤销走的是"重建时间线"，不是回滚字幕。
- **粗剪不保留效果**：重建出的片段不带转场 / Fusion 特效 / 调色节点。
- `App:FindPrev` 已无 UI 入口（v3.1.3 删掉了「◀」按钮），目前是死代码。

## 8. 版本管理与同步工作流（v4.0.7 新增）

- **版本唯一来源**：`01_源码\version.txt`；`sync_version.py` 注入 5 处。
  三段式（v1.0.0 起）：**小更新**（修补/文案）动最右一位 `1.0.1 → 1.0.2`；
  **重要更新**（成组功能、较大修复）动中间一位 `1.0.x → 1.1.0`；
  **超大型更新**（架构调整/不兼容）动最左一位 `1.1.0 → 2.0.0`。
- **双轨同步**：规范源码 `01_源码` ↔ 实时引擎 `D:\AsrSubs\engine`，靠 `sync_dev.py` 保持。
  每次在 engine 改完测试，跑 `python sync_dev.py --sync` 回灌，再按需 `--deploy`。
- **每日巡检**：已建自动化，每日只读跑 `python sync_dev.py`，发现漂移即提示补回灌
  （详见 `03_文档\开发文档.md` §8.4）。
- 完整流程与文件清单见 `03_文档\开发文档.md`。
