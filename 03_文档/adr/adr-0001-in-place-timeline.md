# ADR-0001 · 只在当前时间线原地落轨

| 项 | 值 |
|---|---|
| 状态 | **已接受，永久约束** |
| 决策时间 | 2026-10-31（v4.0.4 起确立） |
| 影响范围 | `land_subtitle.py`、`cut_inplace.py`、所有落轨 / 粗剪入口 |

## 一句话摘要

落轨与粗剪一律在当前已打开的时间线上原地完成，代码里不再保留任何「新建时间线」分支。

## 当前有效结论

- **决策**：绝不新建时间线；`land_inplace` 失败只报错，不静默新建。
- **状态**：已接受的永久约束，2026-10-31（v4.0.4 起）确立，此后未变。
- 理由、后果与失效说明见下文。

## 关键变更（仅影响使用的里程碑）

- 2026-10-31（v4.0.4 起）：确立红线，删除「新建时间线兜底」分支；`land_inplace` 失败改为只报错。
- 2026-11-05：固化为 ADR-0001；`archive\archive-carryover-20261031.md` §6.2 中「必须先新建空时间线」的相反表述同时标为失效。此后未变。

## 背景

早期实现为「新建一条空时间线 → 先落字幕 → 再复制素材」，理由是新建时间线上字幕对齐最稳。代码里曾保留「主路径校验未对齐时自动回退到新建时间线」的兜底分支。该做法在 `archive\archive-carryover-20261031.md` §6.2 被写成了「必须先新建空时间线」。

## 决策

**所有落轨 / 粗剪操作都必须在「当前已打开的时间线」上原地完成，绝不允许新建时间线。** 历史「新建独立时间线」分支已彻底删除；`land_inplace` 失败只报错、不静默新建。

## 理由

- 新建时间线会改变用户工程结构，用户的视频 / 音频 / 特效轨需要整体复制，代价与风险都高于「在当前时间线上复用 / 新建字幕轨」。
- 原地路径通过「边车 `<srt>.landed.json` + 专用字幕轨复用 + 启用态回读校验」已经能稳定对齐，不需要靠新建时间线兜底。
- 项目方明确要求：时间线操作一律原地完成。

## 后果

| 正面 | 负面 / 需遵守 |
|---|---|
| 用户工程的视频 / 音频轨一个片段都不动 | 落轨失败时不能靠「换条时间线」绕过，必须就地报错并回收本次自建的空字幕轨 |
| 换集 / 换时间线不会遗留多余时间线 | 每次刷新字幕轨清单都要重新取 `GetCurrentTimeline()`，不能用开窗时的快照 |

配套规则见 `..\design\design-timeline-ops.md`（顺序铁律、专用轨复用、失败回收）。
